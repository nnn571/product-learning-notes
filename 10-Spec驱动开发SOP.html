      • 02:29—03:16 / 老师以团队经验说写代码效率高、内部更重视审Spec / 经验未独立验证；不采纳“无需代码审查”，也不把10—100倍当承诺
      • 03:16—05:13 / 写Skill与规格驱动开发相通 / 都要把任务、步骤和完成标准连接起来
      • 05:13—08:14 / 用音乐App参考图反推需求与页面 / 可观察布局和交互线索；看到前端不等于知道后台
      • 08:14—09:16 / 老师明确网页只能看到可见界面，无法据此了解全部架构 / 竞品分析标“观察”和“推测”，不能虚构内部API
      • 09:16—10:37 / 模板可以改，不必照搬唯一格式；需写架构、数据、接口、异常 / 要知道数据从哪来、失败如何交代，不能只写正常流程
      • 10:37—14:46 / 剪辑目标同时包括产量和质量；直接AI混剪效果不足 / 分开技术导出、人工质量、业务效果三个账本
      • 12:26—13:50 / 用70/80/85—90分与播放效果解释团队期待 / 这是老师局部经验，评分量表、平台和样本条件不全，不能承诺爆款
      • 14:46—17:39 / 有好成片还不够，工程源文件包含更多编辑决策 / 收集专家过程与理由，产物需要可修改时验工程
      • 17:39—19:51 / 提到通过工程文件/JSON组织剪辑，减少纯界面点击 / 属技术路线；未提供可核版本与完整实现，不据此保证兼容或直接运行
      • 19:51—21:09 / 把剪辑拆成脚本、分镜、素材、精剪、封面、质检 / 每步有明确交接物，避免上一环节问题扩散
      • 21:09—22:01 / 学生提出剧情脚本→分镜→画布、按题材调用Skill / 是方案讨论，未展示价值验证；不推定该学生就是你
      • 22:01—24:05 / 配音多生成候选再择优，反复测试 / “4选1”“100次”是举例，实际次数应由质量收益与费用决定
      • 24:05—24:45 / 强调按真实业务反馈持续迭代 / 专家规则需要实测，不是一次写完即成熟
      • 24:45—25:09 / 素材来自本地/NAS实拍库 / NAS可理解为网络共享存储；先查素材基础，再估自动化范围
      • 25:09—27:20 / 技术、数据、规则三类卡点，尝试找现有工具 / 找到工具后仍需验权限、输入输出和效果；私域业务规则不能凭AI补齐
      • 27:45—29:50 / “说到输入就展示输入框”等精细规则；给背景、SOP、好案例和工程 / 按需要组织与加载材料，不把所有文件无限塞入上下文
      • 29:50—31:23 / 展示视频时出现质量批评及耳机音频路由问题 / 当时没听见声音不能直接判成片无音轨；视频本身未随本次材料提供
      • 31:23—33:25 / 老师说反复迭代后才有初步效果；作业先交初步效果、文档与Demo / 时间与模型体验属个人案例，不是你的完成期限或模型排名
      • 36:10—38:21 / 课后学生讨论问答、提醒、记忆与摄像头功能 / 功能多不证明需求强；提醒要验实际通知，记忆要验取回更新，摄像头要有真实接入
